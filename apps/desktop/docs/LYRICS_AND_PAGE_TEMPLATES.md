# Lyrics and page templates

For the user workflow, see [Usage](../../../docs/USAGE.md). This reference covers
how the desktop provides synchronized lyrics and creates template pages.

## Templates and setup

New configurations start with **Home**, **Music**, **Applications** and **Computer**. Existing
configurations keep their pages and settings when upgrading.

**Add a page** groups templates by purpose and previews both screens before
creation. Every template becomes a normal editable page. Selecting one does not
enable features, connect services or request permissions.

| Template | Top screen | Touch screen |
| --- | --- | --- |
| Home | Automatic: media or applications | Browser, two favorites, capture, microphone and volumes |
| Music | Now playing, synced lyrics or full-screen artwork | Playback, volumes, audio output and artwork toggle |
| Applications | Open applications | Automatically updated window list |
| Computer | System statistics | Compact list: files, terminal, screen lock and settings |
| Streaming | Twitch chat or system statistics | OBS controls, microphone, volumes and settings |
| Notifications | Recent notifications | Detected communication apps and settings |
| Custom | Automatic initially | Empty grid for your actions or an extension source |

Music and Streaming offer display variants within one template. You can change
any page's top screen later in the editor. The gallery points out any setup still
needed: media features, lyrics, notification permissions, Twitch and OBS.
An OBS scene button is included only when scenes are available; otherwise add it
after connecting OBS. The maximum is 12 pages. On Windows, Music uses a mute button instead of
audio-output cycling; select the output through Windows Sound settings.

Setup offers two Home favorites from detected applications and a Music display
choice. Enabling lyrics never adds a separate lyrics page. Notifications can be
added after setup when the feature is enabled and system access is available.
To read lyrics, choose the Music lyrics variant or select **Synced lyrics** in
an existing page's top-screen chooser.

The default pages are defined in `default-config.json`; the frontend reuses those
pages as template seeds. Optional templates and display variants live in
`frontend/src/editor/pageTemplates.ts`. Console icon IDs, names and atlas order
share `apps/console/source/graphics/icon_assets.def`. After changing that manifest,
regenerate the atlases with `node tools/build_console_icons.mjs` from the repo root.

The lyrics dashboard has a configurable accent and 2–5 visible lines. The console
wraps the active line using native font measurements. Seeking is available when
the player provides duration/position and supports it.

## Providers and privacy

Online lookup is disabled by default. Enabling it sends track title, artist and
available album/duration metadata to LRCLIB from the desktop. The console receives
only bounded timestamped text. macOS supplies metadata through its native media
adapters; Windows supplies it through GSMTC. Linux lacks a native media provider.

Disabling online lookup hides downloaded cache results; local LRC files remain
usable. Unsynchronized, instrumental and missing results have explicit states.
No lyrics are generated by the app.

## Local files and cache

The app's configuration directory contains `lyrics/`. A local file is named
`<track-key>.lrc`; downloaded timestamped lines use `<track-key>.json`.
The key is the hexadecimal SHA-256 of UTF-8 text:

```text
lowercase_title + NUL + lowercase_artist + NUL + lowercase_album + NUL + duration_seconds
```

Title and artist are trimmed before deriving the key. Unknown album is an empty
string and unknown duration is `0`. Local LRC files take priority over online data.
The key derivation lives in `src-tauri/src/features/lyrics.rs`.

## Transport limits

Responses/files are limited to 256 KiB, then to 256 lines of 120 UTF-8 bytes each.
A song is sent as one `media.lyrics` frame within the 64 KiB transport limit.
The console tracks time locally and resynchronizes from media state updates.
Lookups are cancelled on relevant track/config changes, with requests spaced at
least 350 ms apart and an eight-second HTTP timeout. HTTP errors are reported;
lookup success and player seek support should be checked independently.
